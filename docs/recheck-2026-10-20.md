## New live findings and fixes

- The eight checked host services were active; NTP was synchronized. Effective SSH settings were `PermitRootLogin no`, `PubkeyAuthentication yes`, and `PasswordAuthentication no`. [Live output](../evidence/recheck-host-live-2026-10-20.txt). Prometheus and Alertmanager readiness checks passed, and the Prometheus query returned `libvirt_up=1`. [Monitoring output](../evidence/recheck-monitoring-live-2026-10-20.txt).
- `ceph1` was running but had libvirt autostart disabled. [The host playbook](../ansible/ceph-host.yml) now starts an existing shut-off guest and enables autostart. The [apply](../evidence/recheck-ceph-host-apply-2026-10-20.txt) made one change; the [repeat](../evidence/recheck-ceph-host-repeat-2026-10-20.txt) had `changed=0 failed=0`. Live `virsh dominfo` shows `Autostart: enable`. A full host reboot was not used as a test.
- The fresh [Ceph node playbook repeat](../evidence/recheck-ceph-node-repeat-2026-10-20.txt) completed with `changed=0 failed=0` after the object read/write test.
- One historical manager-module crash from the unused Ceph `restful` module appeared during this recheck. The module is disabled in automation. After checking the traceback and live manager health, its crash record was archived, not deleted. [Live Ceph output](../evidence/recheck-ceph-live-2026-10-20.txt) then showed no unarchived crash and only the expected pool redundancy warnings. Inspect the archived record if the issue returns, especially after package upgrades.

## Remaining limits

The PDF's requested **partial implementation and written design** are present. Production acceptance would still require independent compute and Ceph failure domains, replicated OSDs, fencing and placement, an off-host monitoring system, a real on-call receiver, and measured tenant-VM recovery objectives. The earlier Gluster guest-level measurement was on three guests sharing one physical failure domain and was retired. Neither that drill nor the one-OSD Ceph test proves host-loss RPO/RTO.
